Hawk · hash-and-sign lattice signature

Sign and verify with the repo’s Hawk code, in your browser

BROKEN Hawk was withdrawn from NIST’s signature process on 29 July 2026, after Straznickas and Weis reduced Hawk-n key recovery to SVP in dimension n/2 + 1. Claimed key-recovery cost fell from 2150 to 2108 for Hawk-512 and from 2288 to 2182 for Hawk-1024, and real Hawk-256 keys were recovered. Teaching demo only.

Run the repo’s Python Hawk implementation

Starts Python in this page (Pyodide 0.29.5, with NumPy and SymPy), imports the repo’s hawk_crypto package unmodified, then generates a Hawk-512 key pair, signs a message and verifies it on your device. Then tamper with what Bob receives and watch verification fail.

About 12.6 MB from cdn.jsdelivr.net, cached after the first run. Nothing you type leaves the page.

Run the repo’s test suite

The repo’s tests/test_hawk.py under pytest 8.3.5 (about 1.6 MB more): round trips, sizes against the spec, tampering, wrong keys, random input and the decoder-fix regressions, for Hawk-256 and Hawk-512 as the repo runs by default. Takes a few seconds to half a minute.


    

  


  

    What runs: the repo’s hawk_crypto package (hawk-py, vendored with the six fixes in PATCHES.md) and its tests, unmodified, in Pyodide 0.29.5 in a Web Worker. The Flask server app.py does not run; glue.py, written for this page, calls hawkkeygen, hawksign and hawkverify directly. Times are measured on your device.
    Source: happyc0der/hawk-signature-study @ 61a3dfa
    Licence: MIT; hawk_crypto/ is from hawk-sign/hawk-py (MIT) by the Hawk team.
    Caveats: key generation and signing are seeded from NumPy’s np.random, upstream’s choice and not a CSPRNG; the Python is not constant-time and runs 10–100x slower than Hawk’s C code.
