Why the calculator tops out near 6 fps

On the eZ80 one byte written to VRAM costs about 122 cycles, so frame time follows painted area. Measured in 32 kHz timer ticks:

frame_ticks = 1204 + bytes_painted × 122 / 1465

Painting the full 320 × 200 view alone takes about 0.16 s, a ceiling of about 6.2 fps however good the renderer is. The readout next to the frame cap shows how long the same game logic and rendering take per frame in this browser.

What runs: the repo's unmodified src/main.c, the file that builds the calculator program, compiled to WebAssembly with a browser port of its SDL2 host harness (src/web.c). Browser speed under a frame cap, not an emulated eZ80. All art is generated by the code at startup.
